## Best open-source references for a pump.fun-style launchpad with Raydium graduation (as of 2026-08)

### Headline conclusions for the planner

1. **No credible open-source pump.fun clone ships a complete, audited Raydium CPMM migration CPI.** The one *audited* open clone (Pump Science, Code4rena Jan-2025) migrates to **Meteora**, not Raydium. The "pumpfun raydium migration" GitHub genre is dominated by dev-shop SEO repos (0 stars, code withheld "for private", repos get renamed/deleted — one search hit was already 404). The correct build path is: audited pump-science architecture for the curve + Raydium's **official CPI adapter crates** for the graduation CPI.
2. **Raydium officially supports this repo's exact toolchain**: `raydium-io/raydium-cpi` has a maintained **`anchor-0.30.1` branch** (updated 2025-08-28) with a `raydium-cpmm-cpi` package. This is the single most important pin found.
3. **Mechanics changed over time**: pump.fun itself stopped graduating to Raydium — the old off-chain `withdraw`-to-Raydium flow is deprecated; since PumpSwap launched (~March 2025) graduation is a permissionless on-chain `migrate` to PumpSwap with LP burned. "Bonding curve → Raydium graduation" is today the **Raydium LaunchLab** model — and LaunchLab's program source is **not** open (only IDL + SDK). So a launchpad that graduates to Raydium CPMM is re-implementing LaunchLab, with pump-science as the closest audited open analogue.

### D. Metaplex metadata CPI from anchor-lang 0.30.1

- Use **anchor-spl 0.30.1 with `features = ["metadata"]`** — it re-exports **mpl-token-metadata 4.1.2** (Cargo pin in anchor v0.30.1 spl/Cargo.toml is `mpl-token-metadata = { version = "4", optional = true }`) and provides `anchor_spl::metadata::create_metadata_accounts_v3` + `CreateMetadataAccountsV3` accounts struct (confirmed on docs.rs for 0.30.1). ### E. bankrun 0.4.0 + dumped Raydium binaries (public precedent exists)

- **solana-bankrun latest = 0.4.0** (published 2024-10-17, no npm deprecation flag), but the project is **deprecated as of ~March 2025 in favor of LiteSVM**; anchor-bankrun had a port-to-litesvm PR merged then reverted; anchor-bankrun ≥0.4 requires anchor-0.30-style IDLs (v0.3.0 for older). No blocker for this repo — 0.4.0 is already proven in-suite — but expect no upstream fixes.
- **Credible public example of exactly the target pattern**: **metaDAOproject/programs** `tests/main.test.ts` (develop branch) — loads `mpl_token_metadata` and AMM programs via `startAnchor` programs list and injects Raydium CPMM config as **account fixtures**: `{ address: LOW_FEE_RAYDIUM_CONFIG, info: { data: fs.readFileSync(<fixture>), owner: RAYDIUM_CP_SWAP_PROGRAM_ID } }`. Also: raydium-io/ray-gauges `sol/tests/util.ts` and Nadunorus/tomo-swap-solana `tests/raydiumCpSwap/initialize.test.ts` reference the CPMM program id in bankrun-style suites. Pump Science's C4 repo also uses bankrun e2e tests against its curve+migration.
- Dump mechanics (documented in Solana cookbook + bankrun tutorial): `solana program dump CPMMoo8L… cp_swap.so` (program) + `solana account <amm_config> --output json` (state), then `programs`/`accounts` params of `start`/`startAnchor`. This repo's `/home/user/dao.fun/scripts/dump-mainnet-programs.ts` already implements the exact pattern (incl. the 45-byte ProgramData header strip and gzipped fixtures) — extend its PROGRAMS/ACCOUNTS lists with the CPMM program, `amm_config`, and the create-pool-fee receiver account.
