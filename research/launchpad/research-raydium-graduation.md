# Graduating a token from a custom bonding curve into a Raydium pool (state of play, Aug 2026)

## 1. Raydium CPMM (CP-Swap) — the modern no-OpenBook target

**Program IDs.** Mainnet `CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C`, devnet `DRaycpLY18LhpbydsBWbVJtxpNv9oXPgjRSfpF2bWpYb` (both declared in `raydium-io/raydium-cp-swap` `lib.rs` and in Raydium's docs program-address table). Repo description is literally "Revamped constant product AMM - no Openbook ID requirement, Token22 support" — CPMM needs **no OpenBook market** and supports Token-2022 mints.

**`initialize` (pool creation) instruction.** Args: `init_amount_0: u64`, `init_amount_1: u64`, `open_time: u64` (if `open_time <= now` the program resets it to `now + 1`). Accounts, in order (20): `creator` (mut, signer, pays), `amm_config`, `authority` (PDA, seed `"authority"` — hardcoded upstream as `GpMZbSM2GgvTKHJirzeGfMFoaZ8UR2X7F4v8vHTvxFbL` on mainnet per SDK usage), `pool_state` (mut; **either** the canonical PDA `["pool", amm_config, token_0_mint, token_1_mint]` **or any random keypair that co-signs** — source: `if pool_account_info.key() != expect_pda_address { require_eq!(pool_account_info.is_signer, true) }`), `token_0_mint` (must sort < token_1_mint by pubkey), `token_1_mint`, `lp_mint` (init, PDA `["lp_mint" seed, pool_state]`, 9 decimals, authority = the authority PDA), `creator_token_0`, `creator_token_1`, `creator_lp_token` (init ATA), `token_0_vault` (PDA `["pool_vault", pool_state, token_0_mint]`), `token_1_vault`, `create_pool_fee` (mut, constrained `address = crate::create_pool_fee_reveiver::ID` — mainnet `DNXgeM9EiiaAbaWvwjHj9fQQLAX5ZsfHyvmYUNRAdNC8`, devnet `3oE58BKVt8KuYkGxx8zBojugnymWmBiyafWgMrnb6eYy`; it is a wSOL ATA — lamports transferred then `sync_native`), `observation_state` (init PDA), then token_program, token_0_program, token_1_program (Token or Token-2022), associated_token_program, system_program, rent.

**Fee & permissioning.** Every current mainnet `AmmConfig` has `createPoolFee = 150,000,000` lamports (**0.15 SOL**), verifiable live at `https://api-v3.raydium.io/main/cpmm-config` (config index 0, the standard 0.25% tier, is `D4FPEruKEHrG5TenZ2mpDGEfu1iUvTiqBxvpU8HLBvC2`; trade fee split: protocol_fee_rate 120000 = 12% of trade fee, fund 40000 = 4%, rest to LPs). `initialize` is **permissionless** unless `amm_config.disable_create_pool` is set; a separate `initialize_with_permission(creator_fee_on)` exists, gated by a `Permission` PDA `["permission", payer]` (admin-granted) — this is the entry point LaunchLab's migration CPIs into (it enables per-pool creator fees / a distinct creator wallet).

**LP minting.** `liquidity = sqrt(amount_0 * amount_1)`; a hardcoded `lock_lp_amount = 100` is subtracted and never minted (permanent floor so the pool can't be fully drained); the rest is minted to `creator_lp_token`.

**CPI examples.** `raydium-io/raydium-cpi-example` (`cpmm-cpi` program) has `proxy_initialize`, **`proxy_initialize_random_pool`**, `proxy_deposit`, `proxy_withdraw`, `proxy_swap_base_input/output`; built with anchor-cli 0.29 / solana 1.17, `--features devnet` flag for devnet, and the repo lists devnet AmmConfig + fee-receiver test accounts. There is also `raydium-io/raydium-cpi` (interface crates) and TS demos in `raydium-io/raydium-sdk-V2-demo` (`src/cpmm/createCpmmPool.ts`, `lockLiquidity.ts`, `harvestLockLiquidity.ts`). IDLs in `raydium-io/raydium-idl` (`raydium_cpmm`, `raydium_clmm`, `raydium_launchpad`).

## 2. AMM v4 vs CPMM vs CLMM — what launchpads migrate to today

- **AMM v4** (`675kPX9MHTjS2zt1qfr1NYHuzeLXfQM9H24wFSUt1Mp8`, devnet `DRaya7Kj3aMWQSy19kSjvmuwq9docCHofyP9kanQGaav`, open source `raydium-io/raydium-amm`): requires a **fresh OpenBook market** (`srmqPvymJeFKQ4zGQed1GFppgkRHL9kaELCbyksJtPX`) not bound to any existing pool; creation fee 0.15–0.2 SOL (docs pages disagree: legacy docs said 0.15 SOL to `7YttLkHDoNj9wyDur5pM1ejNaAvT9X4eqaYcHQqtj2G5`, new fee-comparison page says 0.2 SOL + ~0.15 SOL rent) — plus OpenBook market rent. The OpenBook order-sharing is now deactivated (wiring inert) but the market is still structurally required. SPL-token only, no Token-2022.
- **pump.fun historically** graduated to **AMM v4 + OpenBook market**, charging a 6 SOL migration fee, via its own migrator program/wallet `39azUYFWPz3VHgKCf3VChUwbpURdCHRxjWVowf5jUJjg` (a keeper crank; migrations took minutes). Since **March 20, 2025** pump.fun migrates to its own **PumpSwap** AMM (`pAMMBay6oceH9fJKBRHGP5D4bD4sWpmSwMn52FMfXEA`) via a permissionless `migrate` instruction that creates the pool and **burns the LP**, with the 6 SOL fee eliminated and migration instant.
- **Raydium LaunchLab / letsbonk (BONK.fun)** migrate into Raydium: LaunchLab supports **both** `migrate_to_amm` (AMM v4) and `migrate_to_cpswap` (CPMM), chosen at launch via `pool_state.migrate_type` (0 = AMM v4, 1 = CPMM); **Token-2022 launches must use CPMM**; Raydium's own JustSendIt flow graduates into a **CPMM** pool. New integrations overwhelmingly target CPMM (no market rent, Token-2022, built-in creator-fee + LP-lock hooks); AMM v4 persists mainly for legacy tooling compatibility.
- **Moonshot → Moonit (DEX Screener)**: graduating tokens migrate to **Raydium AMM v4 (LP burned, creator gets 2 SOL bonus)** or **Meteora DAMM v2 (LP permanently locked, dynamic fees 5%→1%)** depending on launch settings; threshold ~432 SOL (~$50k) historically, ~$75k mcap for current Meme Money Markets.
- **CLMM** (`CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK`, open source raydium-clmm) is generally NOT used as a memecoin graduation target (positions need management; Burn&Earn only supports full-range locks).

## 3. Raydium LaunchLab — the closest reference for "own curve → Raydium"

**Program:** mainnet `LanMV9sAd7wArD4vJFi2qDdfnVhFxYSUg6eADduJ3uj`, devnet `DRay6fNdQ5J82H7xV6uq2aV3mNrUZ1J4PgSKsWgptcm6`. **The program source is NOT open** — the raydium-io GitHub org has no launchlab repo; what exists publicly: the Anchor IDL (`raydium-io/raydium-idl/raydium_launchpad/raydium_launchpad.json`, top-level address = LanMV9…), the `raydium-launchlab-sdk` Rust crate on crates.io, TS support in raydium-sdk-V2, and detailed docs at docs.raydium.io (`/products/launchlab/*.md`; full index at `https://docs.raydium.io/llms.txt`). So it's a reference for *interface and flow*, not for code.

**Flow:** launch via `initialize` / `initialize_v2` / `initialize_with_token_2022`; users `buy_exact_in/out`, `sell_exact_in/out` against the curve (JustSendIt default: fixed **85 SOL** graduation target, 1% curve trade fee). When `quote_vault.balance >= quote_reserve_target` the pool status flips **Funding(0) → Migrate(1)**: the curve freezes (no more trades) and awaits migration. Migration is a **separate transaction cranked by Raydium**: the IDL doc-strings on `payer` state verbatim "Only migrate_to_amm_wallet can migrate … must match the migrate_to_amm_wallet saved in global_config" (same for `migrate_to_cpswap_wallet`) — i.e., graduation-completion is user-triggered but **pool creation is a privileged keeper crank**, despite some marketing/docs describing it as 'automatic/permissionless'. After migration: status Migrated(2), `base_mint` mint authority revoked, vesting cliff starts.

**`migrate_to_cpswap`** (no args; 28 accounts): payer(signer, must equal global_config.migrate_to_cpswap_wallet), base_mint(w), quote_mint, platform_config, cpswap_program, cpswap_pool(w), cpswap_authority, cpswap_lp_mint(w), cpswap_base_vault(w), cpswap_quote_vault(w), cpswap_config, cpswap_create_pool_fee(w), cpswap_observation(w), **lock_program, lock_authority (PDA "lock_cp_authority_seed"), lock_lp_vault(w)**, authority (PDA "vault_auth_seed"), pool_state (w, PDA ["pool", base_mint, quote_mint]), global_config, base_vault(w), quote_vault(w), pool_lp_token(w), base/quote token programs, ATA program, system, rent, metadata_program. In ONE instruction it: computes `base_amount_out = base_vault − vesting_locked`, `quote_amount_out = quote_vault − protocol_fee − migrate_fee − platform_fee`, CPIs `InitializeWithPermission` on cp-swap, then splits LP per `PlatformConfig.migrateCpLockNftScale = {platformScale, creatorScale, burnScale}` (must sum to 1,000,000): platform + creator shares are **locked via the LP-lock program with Fee Key NFTs minted**, burnScale is burned. Raydium's default is 90% burned / 10% to creator as a Fee Key NFT earning 10% of pool LP fees in perpetuity.

**`migrate_to_amm`** (args `base_lot_size, quote_lot_size, market_vault_signer_nonce`; 31 accounts incl. openbook_program, market/request_queue/event_queue/bids/asks/market_vault_signer/market vaults, amm_program, amm_pool, amm_authority, amm_open_orders, amm_lp_mint, amm vaults, amm_config, amm_create_fee_destination) — creates the OpenBook market + AMM v4 pool as part of migration.

**Fee sweeping post-graduation:** `collect_fee` (protocol), `collect_migrate_fee`, `claim_creator_fee` (aggregated vault PDA [creator, quote_mint]), `claim_platform_fee` / `claim_platform_fee_from_vault` (PDA [platform_config, quote_mint]).

## 4. Atomicity, cranks, and front-running

- **One-instruction migration is proven on mainnet**: LaunchLab's `migrate_to_cpswap` does curve-drain + CPMM pool creation + LP lock/burn + NFT metadata in a single instruction (28 accounts, 3+ nested CPIs). So "graduation + pool creation in one tx" is feasible within CU/account limits when the pool-creation CPI is the CPMM (v0 tx + address lookup tables give headroom; 64-writable/1.4M-CU limits are not the binding constraint here — tx size is, and 28–31 accounts fits).
- **But the standard architecture is still: curve freezes at completion, keeper cranks the migration.** LaunchLab hard-codes this (status `Migrate` set by the final buy; only the GlobalConfig migrate wallet can execute migration). Pump.fun pre-2025 was the same pattern (migrator `39azUYF…` crank, 6 SOL fee); PumpSwap made the final-buy → `migrate` path instant/free and permissionless because pump.fun controls both programs. Splitting matters for the AMM v4 path (OpenBook market accounts are large) and lets the keeper use lookup tables and retry.
- **Front-running the canonical pool:** cp-swap pools are NOT unique per pair. The canonical PDA `["pool", amm_config, mint0, mint1]` is optional; the source explicitly accepts any random keypair pool_state that co-signs, and the official CPI example ships `proxy_initialize_random_pool`. Consequences: (a) an attacker who buys curve tokens can permissionlessly create a CPMM (or AMM v4) pool for the mint before graduation — you cannot prevent a *competing* pool existing, only make yours the deep/canonical one (routing/aggregators follow liquidity); (b) an attacker squatting the canonical PDA **cannot brick** your migration — fall back to the random-keypair path (your program's own PDA can be the pool account signed via invoke_signed, which is how a CPI caller does it); (c) mitigations used in practice: keep the token non-tradable outside the curve until migration is impossible to front-run economically (pump.fun/LaunchLab tokens ARE transferable, so they simply accept competing pools), have the migration CPI mint/seed in the same tx that completes the curve, and revoke mint authority at migration so no fake supply.
- For AMM v4 the pool address derives from the OpenBook market, so a fresh market always yields a fresh pool — front-running only ever creates a parallel pool there too.

## 5. Burning vs locking LP after seeding

- **Burn**: send LP to a dead address or SPL-burn it (pump.fun/PumpSwap burns; Moonit's Raydium path burns; LaunchLab `burnScale` burns). Simple, but forfeits the 0.25% LP fee stream forever.
- **Lock via Raydium's Burn & Earn / LP-lock program**: mainnet `LockrWmn6K5twhz3y9w1dQERbmgSaRkfnTeTKbpofwE`, devnet `DLockwT7X7sxtLmGH9g5kmfcjaBtncdbUmi738m5bvQC`. LP tokens (CPMM) or a full-range CLMM position NFT are transferred irreversibly into a program-owned escrow (authority PDA seed `"lock_cp_authority_seed"` for CPMM); a transferable **Fee Key NFT** is minted to the caller; the NFT holder can perpetually claim accrued trading fees (`collectFees`/`harvestLockLp` via CPI into the pool program) but can never withdraw principal. AMM v4 hybrid pools are NOT supported by Burn & Earn. The lock program itself is closed-source (no repo, no IDL in raydium-idl) — integrate via raydium-sdk-V2 (`lockLiquidity.ts` / `harvestLockLiquidity.ts` demos) or replicate LaunchLab's CPI account pattern (lock_program / lock_authority / lock_lp_vault / metadata_program). This is exactly how a DAO treasury can keep the graduated pool's fee stream (Fee Key NFT held by the DAO) while making liquidity provably permanent.

## Caveats
- docs.raydium.io was rebuilt in 2026 (raydium-io/raydium-docs-v1, MDX; old `/raydium/...` URLs are dead) and several new pages contain inconsistencies (e.g. "graduation callable by anyone" contradicting the IDL doc-string; AMM v4 fee 0.2 vs 0.15 SOL). The program source, IDL doc-strings, and the live `api-v3.raydium.io` config endpoints should be treated as authoritative; verify against deployed binaries per project doctrine (D-031-style divergence risk applies to Raydium too, though cp-swap/amm/clmm repos are the actual deployed lineage).
- Exact `GlobalConfig` field layout and LaunchLab migrate-fee lamport value weren't publicly enumerated; read them off-chain from the deployed GlobalConfig account or the raydium-launchlab-sdk crate.

## RECOMMENDATIONS
- Target CPMM (CP-Swap), not AMM v4: no OpenBook market, Token-2022 support, open source (raydium-io/raydium-cp-swap), fixed 0.15 SOL creation fee to a hardcoded wSOL ATA, and native creator-fee + LP-lock hooks. AMM v4 is legacy (market rent, SPL-only); CLMM is unsuitable for a graduation target.
- Copy the LaunchLab architecture wholesale — it is the canonical 'own curve -> Raydium' reference even though its program is closed-source: final buy flips curve state to Migrate (curve frozen, trading halted), then a separate migration instruction (restricted to a wallet stored in your global config, i.e., your keeper crank) drains the curve and CPIs cp-swap initialize in one instruction. Its full account lists are recoverable from raydium-io/raydium-idl/raydium_launchpad/raydium_launchpad.json.
- For the migration CPI, base your program on raydium-io/raydium-cpi-example cpmm-cpi (proxy_initialize and especially proxy_initialize_random_pool). Note the example pins anchor 0.29/solana 1.17 — reconcile with the project's proven anchor-lang 0.30.1 / platform-tools v1.53 pipeline (D-029) and, per project doctrine, verify the deployed CPMMoo8L... binary's interface against the repo before trusting enum indices (the D-031 lesson).
- Front-running defense: do NOT depend on the canonical PDA pool address. Since CPMM pools are non-unique, have your migration create the pool at your own program-derived (or keeper-signed random) pool_state via invoke_signed — an attacker squatting the canonical PDA or pre-seeding a competing pool can never block graduation; your pool wins by holding the migrated liquidity. Also revoke the token's mint authority at migration.
- Atomicity: single-tx graduation (final buy + pool creation) is technically possible but no major launchpad does it permissionlessly against Raydium — LaunchLab and legacy pump.fun both freeze the curve and use a privileged crank. For a DAO product, freeze-then-crank is safer: it tolerates RPC failure/retries, allows address lookup tables, and prevents the pool-creation fee/rent from being griefed onto users. Keep the migration instruction idempotent and permissionless-after-timeout if you want liveness guarantees without trusting the keeper.
- LP disposition: prefer locking over burning. Lock the seeded LP via Raydium's Burn & Earn program (LockrWmn6K5twhz3y9w1dQERbmgSaRkfnTeTKbpofwE) so the DAO treasury holds the Fee Key NFT and perpetually claims the pool's 0.25% LP fees — liquidity is provably permanent (escrow is irreversible) without forfeiting revenue. Caveat: the lock program is closed-source with no published IDL, so derive its CPI interface from LaunchLab's migrate_to_cpswap accounts (lock_program, lock_authority PDA 'lock_cp_authority_seed', lock_lp_vault, metadata_program) and the raydium-sdk-V2-demo lockLiquidity.ts, then verify against the deployed binary.
- Budget per graduation on mainnet: 0.15 SOL CPMM creation fee + ~0.04 SOL rent (pool state, vaults, observation, lp mint, ATAs) + lock-position rent; take it from curve quote reserves like LaunchLab does (quote_out = vault - protocol_fee - migrate_fee - platform_fee).
- Fetch live values instead of hardcoding: cpmm AmmConfig list from https://api-v3.raydium.io/main/cpmm-config (createPoolFee, fee rates), and read LaunchLab's GlobalConfig/PlatformConfig accounts on-chain for migrate-wallet and LP-scale examples. Treat the 2026-rebuilt docs.raydium.io pages as descriptive, not normative — at least two pages contradict the IDL (graduation permissioning) and each other (AMM v4 fee 0.15 vs 0.2 SOL).
- Devnet path exists end-to-end: cp-swap devnet DRaycpLY18LhpbydsBWbVJtxpNv9oXPgjRSfpF2bWpYb (build cpi example with --features devnet), devnet fee receiver 3oE58BKVt8KuYkGxx8zBojugnymWmBiyafWgMrnb6eYy, devnet LP-lock DLockwT7X7sxtLmGH9g5kmfcjaBtncdbUmi738m5bvQC — but per project practice (real mainnet binaries in bankrun), pull the mainnet CPMMoo8L... and Lockr... binaries into the hermetic bankrun fixtures instead.
