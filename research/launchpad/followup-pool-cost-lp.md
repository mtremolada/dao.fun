## 2. Fee-payment mechanics, wSOL, mint ordering, pool_state signer

- **Fee receiver is a wSOL token account, program transfers lamports then sync_native.** lib.rs: `pub mod create_pool_fee_reveiver { pub const ID: Pubkey = pubkey!("DNXgeM9EiiaAbaWvwjHj9fQQLAX5ZsfHyvmYUNRAdNC8"); }` (note source typo "reveiver"). initialize.rs account: `#[account(mut, address = crate::create_pool_fee_reveiver::ID)] pub create_pool_fee: Box<InterfaceAccount<'info, TokenAccount>>`. Handler (initialize.rs ~L319-343): `if ctx.accounts.amm_config.create_pool_fee != 0 { invoke(&system_instruction::transfer(ctx.accounts.creator.key, &ctx.accounts.create_pool_fee.key(), u64::from(ctx.accounts.amm_config.create_pool_fee)), …)?; invoke(&spl_token::instruction::sync_native(ctx.accounts.token_program.key, &ctx.accounts.create_pool_fee.key())?, …)?; }`. Docs: "create_pool_fee lamports are transferred from the creator to the receiver and synced as native SOL (it is a wSOL ATA)."
- **SOL side must be pre-wrapped wSOL.** Initial liquidity is pulled only via `transfer_from_user_to_pool_vault(creator, creator_token_0/1, vaults, …, transfer_checked)` from SPL token accounts — there is no native-SOL deposit path (only the fee uses system transfer). The live tx wraps 90,000,000 lamports into a wSOL account (CreateAccountWithSeed + InitializeAccount) before the CPMM ix, and closes it after.
- **Mint ordering.** `#[account(constraint = token_0_mint.key() < token_1_mint.key(), …)] pub token_0_mint` — "Token_0 mint, the key must smaller than token_1 mint." Pubkey `<` is lexicographic over the 32 raw bytes. WSOL = `So11111111111111111111111111111111111111112`. A migrating program MUST branch: if launched_mint bytes < WSOL bytes → token_0 = launched mint (wSOL is token_1); else token_0 = WSOL. In the sampled live tx WSOL sorted below the launched mint and was token_0. `init_amount_0/init_amount_1` and vault sides follow the sorted order.
- **pool_state may be a non-canonical signer.** initialize.rs `create_pool()`: requires `pool_account_info.owner == system_program::ID` (empty account), derives the canonical PDA `["pool", amm_config, token_0_mint, token_1_mint]`, then: `if pool_account_info.key() != expect_pda_address { require_eq!(pool_account_info.is_signer, true); }` — i.e. ANY address works if it signs. Account doc comment: "Or random account: must be signed by cli". The CPI example `proxy_initialize_random_pool.rs` declares `#[account(mut)] pub pool_state: Signer<'info>` and forwards the CPI with `invoke` copying signer flags — a CPI caller can therefore satisfy it with `invoke_signed` on its own PDA (or pass an ephemeral keypair signed at the tx level). Raydium docs confirm the random-keypair path exists as a front-running defence and that all downstream PDAs (lp_mint `["pool_lp_mint", pool_state]`, vaults `["pool_vault", pool_state, mint]`, observation `["observation", pool_state]`) derive from whatever pool_state key is used.
- Note: plain `Initialize` is permissionless but hardcodes `enable_creator_fee = false`; the gated `InitializeWithPermission` (Permission PDA, used by LaunchLab graduations) is the only path that enables the pool creator fee.

## Flags — unverifiable from public sources (measure against the dumped LockrWmn binary / bankrun)

1. **No public source or IDL for the lock program** (absent from raydium-io/raydium-idl). Account writable/signer flags above are the SDK's client-side declarations plus live-tx observation; on-chain constraint details (e.g. whether `fee_nft_account` must be the canonical ATA of `fee_nft_owner`, whether `fee_nft_owner` can be any address type without restriction, whether `with_metadata=false` lets you omit `metadata_account`) are not provable without the binary.
2. **Whether `fee_nft_mint` can be a caller PDA signed via `invoke_signed`** (vs an ephemeral keypair signed at tx level) is untested; both satisfy `is_signer` in principle. Test in bankrun against the real binary.
3. **No live `lock_cp_liquidity` invocation was captured** in the ~65 recent lock-program txs sampled (traffic is dominated by CLMM harvests and `collect_cp_fees`); the lock layout rests on SDK + discriminator-in-binary + docs. Run a bankrun test with the dumped binary before shipping.
4. **Extra payer costs inside the lock tx** (fee-NFT mint 82B, fee-NFT ATA 165B, `locked_liquidity` PDA, Metaplex metadata account rent) were not quantified here — measure them; they are paid by the lock `payer`, not by the CPMM initialize payer.
5. `create_pool_fee` is admin-mutable via `update_amm_config` (param 5) — read it from the AmmConfig at migration time.
6. Minor: `initialize` mints `sqrt(a0*a1) − 100` LP to `creator_lp_token` (`lock_lp_amount = 100` base units permanently withheld) — account for the −100 when locking "all" LP.

## RECOMMENDATIONS
- Reserve at least 192,156,720 lamports for migration overhead (150,000,000 fee + 42,156,720 rent) PLUS the SOL-side initial liquidity PLUS tx/priority fees, but read AmmConfig.create_pool_fee at runtime instead of hardcoding 0.15 SOL — it is admin-settable via update_amm_config param 5 (add an on-curve invariant: reserved_sol >= amm_config.create_pool_fee + 42,156,720 + liquidity + fee margin).
- Implement the mint-ordering branch: byte-compare the launched mint against So11111111111111111111111111111111111111112; the smaller key is token_0 (and drives init_amount_0, creator_token_0, token_0_vault ordering). Write property tests for both orderings — the sampled live tx had WSOL as token_0, so the WSOL-as-token_1 branch is the less-exercised path in the wild.
- Wrap the SOL side before CPI: create/fund a WSOL token account (ATA or account-with-seed owned by the migrating PDA) and pass it as creator_token_0/1; only the create_pool_fee is paid in native lamports by the program. Close the WSOL account after initialize to reclaim its rent.
- pool_state: prefer the canonical PDA ['pool', amm_config, token_0_mint, token_1_mint] (deterministic derivation for downstream PDAs); if front-run occupation of the canonical PDA is a concern, the verified fallback is a program-PDA pool_state signed via invoke_signed — the deployed program only requires is_signer when the key is non-canonical and the account to be system-owned/empty.
- Lock the LP with lock_cp_liquidity setting fee_nft_owner = the DAO treasury PDA (it is not a signer at lock time), lpAmount = minted LP (remember initialize withholds 100 base units), withMetadata = true; harvest later with collect_cp_fees signing fee_nft_owner via invoke_signed — this exact PDA-harvest pattern is live on mainnet (inner-CPI tx CCRMkN… 2026-08-08).
- Per house doctrine (D-031/D-032: never trust public source for deployed binaries), dump LockrWmn6K5twhz3y9w1dQERbmgSaRkfnTeTKbpofwE (last deployed 2025-08-23, upgradeable, 613,677 bytes) and run tests-first bankrun suites for lock_cp_liquidity and collect_cp_fees against the real binary before shipping: verify (a) whether fee_nft_mint accepts a caller PDA via invoke_signed or needs an ephemeral tx-level keypair, (b) whether fee_nft_account must be the canonical ATA of fee_nft_owner, (c) actual writable-flag requirements, (d) rent the lock payer must fund (NFT mint + ATA + locked_liquidity PDA + Metaplex metadata).
- Treat the lock program's upgradeability as a standing risk in REDTEAM.md: the Fee-Key fee stream depends on a closed-source program whose upgrade authority (FytDrVzDybM1TwFQPGb8qaxZR7dBCzNeqT3vtQsceZQK) can change semantics; pin the current binary hash in VERSIONS.md and add a monitor on the programData account's deploy slot.
- If the DAO wants creator-fee revenue on the graduated pool (not just LP fees), note plain Initialize hardcodes enable_creator_fee = false — that path requires Raydium-granted InitializeWithPermission (Permission PDA); LP-fee capture via the Fee Key is the permissionless route.
- Budget compute: the reference initialize tx consumed ~200k CU with a 0.2M limit; set an explicit CU limit and price in the migration tx (also disambiguates byte-identical txs in bankrun per CLAUDE.md gotcha).
